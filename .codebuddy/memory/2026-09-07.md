# 2026-09-07 日志

## 项目初始化
- 工作区原本是空的，从 `https://github.com/1to3fall5/img2mesh` 克隆。
- 结构：`index.html` / `script.js`(约 1000 行) / `style.css` / `split.py`。纯静态、无构建、无依赖管理。
- 定位：上传 PNG/TGA → 抠图生成遮罩 → 轮廓提取 → 三角化 → 导出 OBJ（平面网格，z 恒为 0）。

## 修复「导出 OBJ 破面」
用户反馈导出模型有破面。自建 `tests/mesh-audit.mjs`（算法层）与 `tests/export-check.mjs`（导出链路，vm + DOM stub 跑真实 script.js）定位到 5 个原因：

1. **`optimizeMeshTopology` 复用陈旧边表**（主因）
   翻转就地改写 `indices`，但边表只在迭代开始建一次 → 后续条目读到已被改写的三角形，顶点张冠李戴。
   覆盖率从 1.0 掉到 0.54（丢面）/ 1.20（重叠）。
   修：每轮重建边表 + 翻转前实时校验两三角形确实仍共享该边；`inCircle` 改为绕序无关（乘 orient 符号）。
2. **`traceContour` Moore 邻域起始方向错**
   `startDir = (dirIdx+6)%8` 会让追踪在起点原地转出 2x2 的 4 点死环。
   表现：一个圆盘被拆成 64 条轮廓（1 条主轮廓 + 63 条碎片）；梳状图形 330 条碎片、**主轮廓整块丢失**。
   修：虚拟前驱在西侧 → 初始 `dirIdx=2`（向东），`startDir=(dirIdx+5)%8`（来向的下一个）。
3. **孔洞被填实**：`findContours` 只找外轮廓，图形中间的洞被当实心三角化。
   修：新增 `findPolygons`，洪泛区分「与图框连通的背景(2)」与「孔内背景(0)」，第二轮用 `右邻==0` + 反向追踪找孔，再按点在多边形内挂到宿主外轮廓；作为 earcut 的 `holeIndices` 传入。
4. **earcut 静默丢洞**：`findHoleBridge` 在某些几何/精度组合返回 null → 洞被吞（非单调，0.1/0.2/0.3/0.8px 失败、0.5/1.0/1.5/2.0px 通过）。
   修：`buildPolygonMesh` 三角化后校验「Σ三角形面积 == 多边形净面积」，偏离 >2% 就换简化容差重试（上限 = 周长/200）。
5. **`exportModel` 法线全朝 -Z**：图像 y 向下 → 3D y 向上的翻转使绕序整体反转，开背面剔除的软件里模型不可见。
   修：按最终 3D 坐标算 nz，为负就交换后两个索引，强制法线朝 +Z。

验证：11 个合成图形 × 4 档容差，覆盖率全 1.0、零自交/零退化/零重叠；孔洞数与连通域分析一致；导出 OBJ 法线 20/20 朝 +Z。

## 环境坑
- git 默认 `http.sslBackend=schannel` 访问 github.com 报 `SEC_E_INVALID_TOKEN`。
  `ls-remote` 换成 `-c http.sslBackend=openssl` 即可，但 **push 大包仍失败**（`packet length too long`）。
  最终走 GitHub Git Data API 提交（blobs → trees → commits → PATCH ref），成功。
- commit message 用 PowerShell `-m` 传中文会被控制台编码破坏 → 改用 `git commit -F <UTF-8 文件>`。
